# Am9511 APU core

`fpga/src/am9511.v` is an Am9511A-compatible arithmetic processor behind Z80 ports 0x50/0x51 (0x70/0x71 with JP4). Its behaviour follows the [ratboy666/am9511](https://github.com/ratboy666/am9511) emulator (MIT licence), and it implements the **full command set**.

Two Python files define it exactly:
- `fpga/sim/apu_model.py` covers the basic operations;
- `fpga/sim/apu_ucode.py` holds the derived-function microcode, its assembler and an interpreter.

The hardware matches them bit for bit.

## Programming model (same as the chip)

| Port | OUT | IN |
|---|---|---|
| 0x50 | push a byte onto the 16-byte stack | pop a byte |
| 0x51 | command | status |

- **Stack order:** operands are pushed least significant byte first and popped most significant byte first. The stack is a 16-byte ring: 8 × 16-bit, or 4 × 32-bit / float.
- **Command byte:** `SR | type | op`.
  - `type` 0x60 = 16-bit integer, 0x20 = 32-bit integer, 0x00 = float.
  - `op` is the low 5 bits, e.g. ADD 0x0C, so SADD = 0x6C, DADD = 0x2C, FADD = 0x10.
- **Status byte:** `BUSY SIGN ZERO ERR[4:1] CARRY`.

  | Error code | Value |
  |---|---|
  | DIV0 | 0x10 |
  | NEG | 0x08 |
  | ARG | 0x18 |
  | UND | 0x04 |
  | OVF | 0x02 |

- **Float format:** byte 3 = sign + 7-bit two's-complement exponent; bytes 2..0 = 24-bit mantissa with an explicit leading 1. The value is 0.M × 2^E. A number is zero when mantissa bit 23 is clear. PUPI pushes π as 0x02C90FDA.
- **While BUSY:** data and command accesses hold the Z80 in WAIT, as the real chip's PAUSE does. Status reads always answer straight away. Most commands take under 6 µs. The longest is PWR at 57 µs, which is far faster than the original chip and well inside the bus controller's 500 µs WAIT limit.
- **SR bit:** setting bit 7 of a command raises SVREQ when it completes. SVREQ drives INT* through Q10 and reaches the bus only if JP2 is fitted. The next command or a status read clears it.

## Commands

| Group | Commands | Result |
|---|---|---|
| Stack | NOP, PUPI, PTOS/PTOD/PTOF, POPS/POPD/POPF, XCHS/XCHD/XCHF | exact |
| Integer (16/32-bit) | ADD, SUB, MUL (lower), MUU (upper), DIV, CHS | exact, including CARRY/OVF/DIV0 |
| Float | FADD, FSUB, FMUL, FDIV, CHSF, SQRT | correctly rounded (round to nearest even); exponent wraps on OVF/UND |
| Conversion | FLTS, FLTD, FIXS, FIXD | exact (FIX truncates toward zero) |
| Derived | SIN, COS, TAN, ASIN, ACOS, ATAN, LOG, LN, EXP, PWR | microcoded; accuracy below |

**Domain errors** follow the reference. In every error case the stack is left unchanged.
- **NEG:** SQRT, LN, LOG of a negative number; PWR with a negative base.
- **ARG:** EXP with \|x\| > 32; ASIN or ACOS with \|x\| > 1; PWR when \|A·ln B\| > 32.

## Derived functions

They run as a microprogram of 312 words, with 54 constants, held in block RAM. The program drives the same arithmetic hardware as the basic commands, working on eight internal scratch registers, so the **user's stack below TOS is preserved**.

The microcode has its own one-clock steps besides the float arithmetic:
- load a constant, move, negate, absolute value;
- scale by 2^N, extract the exponent;
- branch on sign, zero or a bit of N;
- call and return.

| Function | Method |
|---|---|
| EXP | n = round(x·log₂e). r = x − n·ln2, using a two-part ln2. e^r ≈ 1 + r + r²·Q(r) with Q of degree 5. Then scale by 2^n |
| LN | x = m·2^k. f = m − 1, or 2m − 1 when m < √½. ln(1+f) ≈ f − f²/2 + f³·P(f) with P of degree 7. Add k·ln2 in two parts |
| LOG | LN × log₁₀e |
| PWR | EXP(A × LN(B)) |
| SIN, COS | j = trunc(\|x\|·4/π), rounded up to even. r = \|x\| − j·π/4, using a three-part π/4. Sine or cosine polynomial by octant, with the sign set from the octant |
| TAN | Same reduction, tan r ≈ r + r·z·T(z). −1/tan in odd quadrants. Returns x itself when \|x\| < 2⁻¹² |
| ATAN | Reduce with tan(3π/8) and tan(π/8). Odd polynomial |
| ASIN | Polynomial for \|x\| ≤ ½; otherwise π/2 − 2·asin(√((1−\|x\|)/2)) |
| ACOS | π/2 − asin x for \|x\| ≤ ½; otherwise 2·asin(√((1−\|x\|)/2)), or π minus that for negative x |

The coefficients are weighted least-squares fits made by `apu_ucode.py`.

**Accuracy** is measured against the true value, in units of the last place of a 24-bit result, over 4,000 random arguments per function:

| Function | Max ulp | Mean ulp | Correctly rounded |
|---|---|---|---|
| SIN | 1.18 | 0.29 | 86% |
| COS | 1.37 | 0.31 | 82% |
| TAN | 2.20 | 0.38 | 74% |
| ASIN | 2.11 | 0.44 | 69% |
| ACOS | 1.16 | 0.38 | 67% |
| ATAN | 2.18 | 0.39 | 64% |
| LOG | 1.70 | 0.41 | 67% |
| LN | 0.71 | 0.25 | 97% |
| EXP | 0.89 | 0.27 | 90% |
| PWR | 25 | 2.7 | 21% |

**PWR** computes A·ln B in single precision, as the original chip does. Its error therefore grows with \|A·ln B\| (up to 32): it is a few ulp for modest powers and worse for big ones. The reference emulator does that step in double precision, so its PWR results are more accurate. Giving the microcode an extended-precision LN would close the gap, if it turns out to matter.

## Where it deliberately differs from the reference emulator

1. **SUB carry is the true borrow.** The emulator's `sub16` signals a borrow whenever the minuend is 0x8000. In a 32-bit subtract that also corrupts the result: 0x00008000 − 0 gives 0xFFFF8000.
2. **32-bit MUL/MUU** test *both* operands for 0x80000000. The emulator tests the first one twice (a typo).
3. **FIXD of +2³¹ reports OVF.** In the emulator this is undefined behaviour in C.
4. **Float results below 2⁻¹²⁶** are rounded to the full 24 bits. The emulator goes through an IEEE single, whose denormals lose precision there.
5. **TAN of a small negative argument** returns the argument. The emulator only does that for positive arguments, so it returns negative inputs unchanged regardless of size.
6. **LN/LOG of 0** reports NEG. The emulator returns 0 with no error.
7. **PWR with base 0** reports ARG. In the emulator the result depends on how the C library handles infinities.
8. **SIN, COS, TAN with \|x\| ≳ 1.7×10⁹** report ARG, because the octant count overflows. At that size a single-precision argument has no fractional precision left anyway.
9. **Derived-function results** are within the accuracy shown above, not bit-identical to the C maths library.

## Verification

- `sim/run_apu_sim.ps1` regenerates the microcode, builds the expected results from the models, and runs them as Z80 port cycles through the full FPGA top level.
- **Last run: PASS.** All 5,216 status and result bytes are identical. The run covers:
  - directed edge cases for every command;
  - 700 random basic operations;
  - 300 random derived-function calls, including domain errors and the SR bit.
- The model's float rounding agrees exactly with the reference's IEEE-single arithmetic on 80,000 random operations and 5,000 square roots.
